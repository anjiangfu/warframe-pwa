## 导入、导出与恢复

1. 原 HTML 中先“导出存档（JSON）”，得到 version=1 的个人备份。`data/tech-tree-seed.json` 仅是目录，不能代替个人备份。
2. 在“备份与恢复”选择文件。旧档上限2 MiB；新格式完整备份文件上限8 MiB（含旧原件）。保存、导出、导入统一按档案本身计算深度20及50,000个值，备份外层不额外占用档案深度。先校验并展示节点/步骤/库存/预算/日志/未知项、hash和冲突。
3. 默认新建档案；也可明确选择已有档案整档恢复。勾选确认后才写入，取消不写库。目标 revision 变更必须重新预览。
4. 覆盖前在同一事务保存旧状态恢复点；任何备份/写入失败使事务中止。重复确认不重复写入，同备份可恢复到另一个档案；后续编辑后可重新预览恢复同一备份。
5. “导出完整备份”包括所有业务字段、自定义节点、归档和旧原件，不包括可重建的在线缓存。旧文件原字节及 SHA-256 保留，可以下载原件；新备份导入会校验其中原件 hash。
6. 未识别节点、旧步骤和字段在容量限制内保留。目录更新不会删除个人状态；当前界面未关联的内容仍在完整备份中。

浏览器清理/卸载/存储回收可能影响本地档案，应定期导出到自己保管的位置。M0 没有删除档案或清库快捷按钮。测试仅使用隔离浏览器/专用档案，没有清理用户真实资料。

完整备份使用紧凑JSON，无损保留业务字段及原件。业务负载（除id/revision外的整个档案，含笔记/日志/归档/原件）UTF-8大小上限8,386,560字节，即8 MiB减2 KiB；预留空间容纳目标id/revision和备份头，id及catalogVersion最多100个字符。表单保存和迁移提交前也检查同一上限，因此不会先报保存成功、再产生无法回导的备份。超限明确拒绝，不裁剪数据；旧版本已保存的超限档案仍保留，导出会显示“备份未生成”并且不下载文件，不能把该提示当作已备份。

## PWA 安装、离线与更新

在支持的正常浏览器会话中，首次在线打开生产站点后，可用浏览器地址栏/菜单的安装入口。Chrome 的 manifest/图标/安装条件已在 Windows 隔离正常档案中检查；未执行 Windows OS 级安装和卸载。隐身模式不能安装。

离线缓存仅含同源应用壳、构建资源、小型目录（已打入应用）、图标和运行依赖许可文本。可以断网关闭页面后重开 `/#tree`、`/#profile`、`/#backup`、`/#log`。首次从未加载过的站点无法凭空离线打开。

新版本缓存完成后提示“新版本已准备好”；可稍后更新。选择保存后更新时，所有打开页面暂停新编辑，等待写入、检查未提交表单，再建立数据库写屏障；无响应旧页会阻止激活，关闭该页后重试或取消。有未提交表单时先取消更新、保存表单，再更新。更新后各页重开，保留数据。只删除本应用旧 `tenno-shell-*` 缓存，不删除 IndexedDB。

更新会话token保存在本应用候选版本缓存中，不含个人资料；页面刷新、发起页关闭或worker被浏览器停止后，可重新加入更新会话，其他页面也可取消。取消按token解除对应数据库写保护；没有等待worker的旧屏障显示“更新保护待处理”，可明确取消后继续写入。不会因等待超时自动解除写保护。所有旧受控页面均关闭时，浏览器可以正常自动激活新版本；重新打开后匹配新构建的屏障会清除。

构建 ID 默认由源文件/依赖锁/静态资源/base的内容hash生成，避免新代码复用旧缓存。`APP_BUILD_ID=m0-v1/m0-v2` 仅用于自动化升级测试；发布不同内容时不能复用同一个手动ID。

数据库版本不兼容时停止写入并显示提示；不删库、不降级、不以模板覆盖。未来升级必须通过一致快照及回滚测试。DB version、备份schema、catalog版本、应用构建ID互相独立。
