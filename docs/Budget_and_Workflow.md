## Codex能否指挥其他 Agent？

可以做成**受控编排**，但授权取决于工具是否支持 CLI/API/本地 MCP，不能因为允许 Codex 执行命令，就自动拥有 CodeBuddy/WorkBuddy 私有平台的管理接口，也不能凭空实现跨 App 调度。

安全可落地的三步：
1. Codex 生成带验收标准的 Git issue / markdown任务，并选定独立子目录或 worktree。
2. 用户在 CodeBuddy / WorkBuddy / DeepSeek+OpenCode 中打开同一仓库的**独立分支**并发送任务；若工具有确切受支持的可编程接口，再评估自动调用。
3. 低成本 Agent 产出 commit / patch；Codex 审查、跑测试、再合并。保留用户对联网、API费用、危险命令的审批。

不建议让 Codex 直接借你的账号网页登录多个第三方 Agent、分享服务密钥，或者给它们长期开启全盘文件/终端权限。若以后开启自动化，按最小权限原则，仅允许运行在限定工作目录、费用上限、操作日志可检查的任务。

## 流程

`TennoHub 审计` → `Codex M0` → `Codex M1` → `低成本 Agent：中文名称表/样式等独立任务` → `Codex 测试和合并` → `M2任务推荐` → `M3装备Wiki` → `M4官方活动`。

中间可以随时添加需求：写入 `docs/changes/` 变更单：用户故事、范围、受影响字段、是否需要数据迁移、验收标准、优先级。禁止 Agent 未经确认擅自改总架构。
